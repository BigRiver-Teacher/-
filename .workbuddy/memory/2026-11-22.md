# 2026-11-22 工作日志

## 监控大屏「实时体征曲线」修复与接入模拟实时数据（frontend/src/views/Echart-monitor.vue）

- 需求：①加速度显示改为 0.75g；②修复切换监护对象后曲线异常，确保绑定当前对象且不残留旧数据；③接入模拟数据并定时滚动刷新，保持其它交互正常。
- 加速度单位根因：后端 `MonitorEchartMapper.selectAccelerationData` 是 `ROUND(AVG(speed)*100,0)`，即步速(m/s)×100，页面却按「加速度(g)」直接显示 → 出现 `75 g`。心跳同源，是 `AVG(frequency)` 步频，页面标 bpm。
- 切换异常的真实原因（4 个叠加）：
  1. **共用数组引用**：`seedWave` 里 `heartCurve.categories = cats` 与 `accCurve.categories = cats` 是同一个数组，`pushSample` 每轮 push 两次时间标签、只 push 一个数据点 → X 轴与数据错位，曲线折返成锯齿。改为 `[...cats]` 各持一份。
  2. **整体替换数据没有 notMerge**：切换对象时用 `setOption` 合并模式更新，ECharts 把旧曲线的点插值到新位置，出现两线交叉的乱线。改为 `resetVitals()` 用 `setOption(fullOption, true)` 重建。
  3. **后端数据稀疏**：`LIMIT 20` 按分钟分组，部分老人只有 1 条步态记录 → 折线图只有单点且 `showSymbol:false`，视觉上「曲线消失」。
  4. **快速切换竞态**：旧对象的接口响应晚到会覆盖新对象数据。加 `activeElderId` 令牌，响应回来若已切换则丢弃。
- 模拟数据方案：36 点滚动窗口（≈1 分钟），`setInterval` 每 1.6s 追加一个采样点，超出即 `shift()`，保证窗口内永远只属于当前对象。
  - 心率：双频正弦（13s / 4.7s）+ 微噪声构成目标值，再用一阶滤波（0.42）逼近，相邻点差值很小 → 曲线自然平滑；基线取当前对象 `heartbeat` 接口均值并 clamp 66~96，缺失时回落 78。
  - 加速度：基线固定 `ACC_BASE = 0.75`，正弦幅度 ±0.045 + 1.5% 概率的体位尖峰（+0.03~0.06），clamp 0.64~0.88，读数稳定在 0.71~0.79。
  - 首屏种子窗口末位锚定基线，打开页面即显示 `0.75g`。
  - y 轴按基线固定范围（心率 ±10、加速度 0.62~0.9），避免每帧自适应导致曲线上下跳。
  - `animationDurationUpdate = TICK_MS*0.8` + `linear`：新点推出、旧点左移，形成连续滚动示波器效果。
- 其它：去掉 `getMonitorAcceleration` 调用（该接口返回步速，不是加速度）；`onMounted` 改为 `Promise.all([elderList, deviceStatus])` 后再 `bindElderVitals(currentElder)`，否则首个对象为 null 导致基线回落到默认值；`onUnmounted` 清定时器；工具提示按单位格式化（`95 bpm` / `0.75 g`）；体征面板标题右侧加呼吸圆点表示正在实时采集。
- 验证：`npm run build` 通过；实测 10s 内数值变化 5 次（≈0.5 次/秒，即 1.6s 一帧）；切换 张建国→王德发→张建国→李秀英 均即时重建曲线（96 bpm → 80 bpm），无锯齿、无残留；离开页面再回来无重复定时器；其它三页 canvas 数 5/5/4 无回归；0 console 错误。
