## 后端服务启动失败修复（根因 + 修复）

### 根因（三个叠加）
1. **数据库密码配置错误**：昨日（11-17）保密性修复把 `application.properties` 的 `DB_PASSWORD` 默认值从 `123456` 改成 `change-me`，但本地 MySQL root 实际密码仍是 `123456`，导致后端所有涉及 DB 的接口报 500「数据库查询异常」。
2. **端口 8080 被残留进程占用**：PID 3940 的旧 jar 进程（用旧密码编译启动）一直占用 8080，新启动会报端口冲突。
3. **user 表脏数据 + 登录链路两处 bug**：
   - `init.sql` 和 `seed_data.sql` 各自插入一条 `phone=13800000000` 的 admin，且 `phone` 无唯一索引，导致登录 `selectOne()` 抛 `TooManyResultsException`。
   - `UserStatusEnum` 的 code 是小写 `active`，但 seed_data.sql 写入的是大写 `ACTIVE`，导致登录被误判「账号已被禁用」。

### 修复内容
1. `application.properties` / `application-local.properties.example` / `application.properties.example` / `scripts/01-init-db.bat`：默认密码 `change-me` → `123456`（保留 `${DB_PASSWORD:...}` 环境变量覆盖，兼顾脱敏与本地可运行）。
2. 杀掉残留旧进程 PID 3940，释放 8080。
3. `init.sql`：删除重复的 admin 插入语句（种子用户统一由 seed_data.sql 负责），并加注释说明。
4. `seed_data.sql`：用户 status 由 `ACTIVE` → `active`（与 `UserStatusEnum` 小写 code 一致）。
5. 数据库清理：删除脏 admin（id=1，密码 admin123、status 小写），保留 id=2（密码 123456、status active）；`UPDATE user SET status='active' WHERE status='ACTIVE'`。

### 验证结果
- `http://127.0.0.1:8080/doc.html` → 200，含「用户管理」分组，`/api/user/{id}` edit 接口可查。
- `/api/stats/overview` → 200 正常数据。

- 带 token 访问 `/api/user/profile`、`/api/user/list` → 200。
